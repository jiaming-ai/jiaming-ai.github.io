Tokenization（含动作 token 化）

Transformer 只会读写一串离散的符号（token）。文字、图像和机器人动作都得先变成 token 序列：文字用 BPE 切成子词，图像切成小块，连续的动作则可以按维度均匀分箱（RT-1、RT-2、OpenVLA 的做法）、先做 DCT 再用 BPE 压缩（FAST），或者查一本学出来的码本（VQ）。本节在浏览器里把一条机器人轨迹 token 化再还原回来，看清分辨率、序列长度和平滑性三者之间的取舍，并亲手训练一个“对 token 做分类”的动作头，看它为什么能表示多峰的示范。

    1为什么机器人需要它

    17.3 节的 Transformer 处理的是一串向量，而这串向量通常来自一张查找表：每个位置先是一个整数 \(k\in\{0,\dots,V-1\}\)，再查出它的嵌入向量。输出端也一样：语言模型在每个位置输出一个对 \(V\) 个整数的 softmax 分布，训练用交叉熵（16.1 节），生成时一个一个地采样（19.4 节）。这个整数就是 token，把原始数据变成 token 序列、并能从 token 序列还原回来的那一对函数，就是 tokenizer。

    对文字来说，tokenizer 早已是标准件。机器人的麻烦在于它要同时处理三种完全不同的东西：一句指令（“把红色方块放进碗里”），几路相机图像，以及一串连续的动作，比如每秒 50 次的末端位移和夹爪开合。如果想直接复用一个在互联网文本和图片上预训练好的大模型（这就是 RT-2、OpenVLA 这类“视觉-语言-动作模型”VLA 的思路），最省事的办法是把动作也变成 token，让模型像“说话”一样“说出”动作。

    可动作 token 化不是小事：切得太粗，机器人手抖、对不准；切得太细，序列太长，推理变慢，模型学起来也更难；切的方式不对，还会让轨迹在块与块之间跳变。本节依次看文字、图像和动作的 token 化，重点放在动作上：均匀分箱、FAST（DCT + BPE）和 VQ 码本，以及它们在分辨率、序列长度和平滑性上的取舍。

    2直觉：token 是一本字典里的页码

    任何 tokenizer 都在做同一件事：准备一本有 \(V\) 个条目的字典，把输入切成片段，每个片段写成它在字典里的编号。字典越大（\(V\) 越大），每个条目能表示的东西越多，同样的内容用的 token 越少；字典越小，序列越长。对文字，最常用的字典是 BPE（byte-pair encoding，字节对编码）学出来的：从单个字符开始，统计语料里哪两个相邻符号一起出现得最多，就把它们合并成一个新符号 \(\hl{merge}{(a,b)\to ab}\)，加进字典，重复若干次。常见的词因此变成一个 token，罕见的词被拆成几个常见的片段，而且任何由已知字符组成的字符串都能被编码，不会出现“未登录词”。

    下图在一小份机器人指令语料（35 句，如“pick up the red cube”）上实时训练 BPE。拖动合并次数，看同一句话的切分怎样从一个个字符变成整词。“▁”标记一个词的开头（SentencePiece 的写法），所以“▁the”和词中间的“the”是两个不同的 token。

    试一试
    • 用默认句子，增加合并次数，直到“gripper”成为一个 token（第 36 条合并时出现）。这时整句从 33 个字符缩到 16 个 token；到 60 次合并时只剩 7 个，一个词一个 token。
    • 合并次数至少 50 时，在输入框里打一个语料里没有的英文词（例如 “grippers” 或 “redcube”）：它被拆成两个以上已知的片段，而不是变成“未知词”。

    图像：切成小块，每块一个 token

    图像通常不查字典，而是直接切成 \(\hl{patch}{P\times P}\) 的小块，按行优先的顺序排成一串，每块的 \(3P^2\) 个像素值经过同一个线性层变成一个嵌入向量，再加上位置编码：这就是 ViT 的做法（17.3 节讲了它的 Attention 部分）。这里的“token”是连续向量而不是整数，但它在 Transformer 里扮演的角色和文字 token 完全一样。块越小，细节越多，token 越多，而 Attention 的代价按 token 数的平方增长。

    • 选出恰好给出 64 个 token 的块大小，再把鼠标移到红色方块所在的一个块上，读出它在序列里的位置。
    核心洞见

    所有 tokenizer 都在三样东西之间做取舍：保真度（还原回来和原来差多少）、序列长度（Transformer 的计算和延迟随它增长）和字典大小（输出 softmax 有多宽，每个条目要多少数据才学得好）。BPE 用更大的字典换更短的序列；更大的图像块用更少的细节换更短的序列。动作 token 化面对的是同一个三角，只是多了一条机器人特有的要求：还原出来的轨迹必须平滑、连续。

    3动手：把一条轨迹切成 token 再还原

    现在轮到动作。设机器人的末端在平面里走一条 1 秒长的轨迹，控制频率为 \(f\)：每秒发出 \(f\) 个动作，每个动作有 \(D=2\) 维（\(x\) 和 \(y\)，已归一化到大约 \([-1,1]\)）。最简单的 tokenizer 是 RT-1 和 RT-2 用的按维度均匀分箱：对每一维，把训练数据的取值范围 \([a_{\min},a_{\max}]\) 等分成 \(N\) 个箱子，宽度为 \(\hl{delta}{\Delta}=(a_{\max}-a_{\min})/N\)，一个动作值就写成它所在箱子的编号；还原时取箱子的中点。于是每个时刻产生 \(D\) 个 token，1 秒的轨迹产生 \(D\cdot f\) 个。

    下图左边是轨迹在平面里的样子，紫色圆圈是可以拖动的路径点；右边是两维随时间的变化。改箱子数、取值范围的定法、控制频率，看还原误差、token 数和“重复率”怎样变。

    • 找出使 RMSE 低于 0.01 的最小箱子数（默认轨迹、20 Hz 时是 64；32 个箱子时为 0.011）。注意箱子数每翻一倍，误差大约减半。
    • 在 16 个箱子、“最小–最大”范围下打开“含故障的示范”：RMSE 从 0.023 涨到 0.065，几乎三倍；再换成“1%–99% 分位数”：回到 0.022。
    • 把控制频率提到 40 Hz 以上、箱子数不超过 16：超过 40% 的 token 和前一个完全相同（50 Hz、8 个箱子时是 70%）。
    看到了什么

    (1) 分辨率只由箱子宽度决定：误差不超过 \(\Delta/2\)，均方根约为 \(\Delta/\sqrt{12}\)（第 6 节）。默认 8 个箱子时公式给出 0.049，实测也是 0.049。(2) 范围和箱子数一样重要：一个离群值就能把箱子撑宽好几倍，所以 OpenVLA 用 1% 和 99% 分位数定范围。分位数的代价是最极端的 1% 被截断到两端的箱子里；对这条平滑的路径，这几乎没有损失。(3) 序列长度是 \(D\cdot f\)，和箱子数无关：频率越高，token 越多，而相邻 token 也越来越像，大量 token 只是在重复前一个。下一节会看到这对自回归模型很不利。

    4另外两种动作 tokenizer：FAST 与 VQ 码本

    FAST：先变换到频域，再压缩

    FIG 3 的重复率揭示了逐时刻分箱的根本问题。自回归模型逐个预测 token，训练信号来自“给定前面的 token，下一个是什么”。频率高时，下一个 token 几乎总等于上一个，模型只要学会“抄上一个”就能把损失降得很低，真正有信息的变化反而被淹没。FAST（Pertsch 等，2025）的论文正是这样描述高频灵巧任务上分箱的失败：模型陷入抄写前一个动作的局部最优。

    FAST 的办法借自 JPEG：对 1 秒长的动作块，每一维单独做离散余弦变换（DCT），得到 \(H\) 个频率系数 \(\hl{coef}{c_{d,k}}\)。平滑的轨迹几乎所有能量都在最低的几个频率里，高频系数接近零。把系数乘以缩放因子 \(\gamma\) 后四舍五入为整数，大部分高频系数直接变成 0。再按“先低频、各维交错”的顺序展平成一串整数，最后用在大量动作数据上训练好的 BPE 压缩：成串的 0 和常见的组合被合并成一个 token。于是 token 数取决于轨迹有多复杂，而不是控制频率有多高。

    • 选 50 Hz（逐时刻分箱要 100 个 token），在 BPE 打开的情况下调 \(\gamma\)，使 FAST 只用不超过 20 个 token 且 RMSE 低于 0.02（\(\gamma=10\) 时平滑轨迹是 13 个 token、RMSE 0.015）。
    • 体会取舍：把 \(\gamma\) 降到 2 以下，token 更少但 RMSE 超过 0.04（轨迹被抹平）；再升到 30 以上（频率 ≥ 20 Hz），RMSE 低于 0.01 但 token 变多。

    两个值得注意的细节。第一，把 BPE 关掉（合并数 0），FAST 的 token 数和逐时刻分箱一样多：DCT 本身不缩短序列，它只是把信息集中到少数系数上，让大部分整数变成 0；真正缩短序列的是 BPE。第二，换成“抖动”轨迹（叠加了 7 Hz、幅度 0.04 的颤动），高频系数不再为零，token 数随之上升：FAST 的序列长度反映的是轨迹的复杂程度。频率低于颤动频率的两倍（这里是 14 Hz）时颤动会混叠，采样根本表示不了它。

    VQ：学一本动作片段的码本

    分箱和 FAST 都是人工设计的变换。另一条路是让数据自己决定字典：把动作切成长度为 \(L\) 的小块（一个“动作片段”），在大量示范上用 k-means（18.1 节）聚出 \(K\) 个中心 \(\hl{code}{\mathbf e_k}\)，即码本，每个片段用离它最近的码字的编号表示。这是向量量化（VQ）。VQ-VAE 把同样的最近邻查表放进一个可训练的自编码器里，码本和编码器一起学；VQ-BeT 用多级的“残差 VQ”给动作片段编码。这里用最朴素的版本：直接对动作片段做 k-means。

    动作用的是常见的增量形式：每一步的动作是末端位移 \((\Delta x,\Delta y)\)，一个片段就是 \(L\) 个连续的位移，即 \(2L\) 维向量。每个片段只需一个 token，所以 20 Hz、\(L=4\) 时每秒只有 5 个 token。代价是：\(K\) 个码字要覆盖所有可能的片段，片段越长越难覆盖，误差越大；每个片段执行完时，末端位置和真值之间会有一个跳变。本图假设机器人在每个片段开始时重新观测到自己的真实位置（闭环执行），所以误差不会跨片段累积，但会在片段边界上形成跳变。“残差 VQ”再用第二本码本量化第一本留下的误差，每个片段 2 个 token。

    • 用 \(K=16\)、\(L=4\)、单级，训练到收敛：RMSE 约 0.14。再切到“2 级（残差）”并训练：每个片段多用一个 token，RMSE 降到一半左右（约 0.08）。
    • 把片段长度改为 \(L=10\)（每秒只剩 2 个 token），\(K=16\)，训练到收敛：片段边界上的平均跳变约 0.8（\(L=4\) 时约 0.23），轨迹明显“断成几截”。
    一个想法，三种切法

    分箱：每个时刻、每一维独立量化。简单、可解释、不需要训练，但序列长度 \(D\cdot f\) 随频率线性增长，相邻 token 高度冗余。 FAST：先用一个固定的正交变换（DCT）去掉冗余，再用 BPE 做无损压缩。token 数随轨迹复杂度变化，误差由 \(\gamma\) 控制，可证明有界。 VQ：从数据里学一本码本，一个 token 代表一整段动作，序列最短，但码本外的动作表示不好，片段边界会跳。三者在第 2 节的三角里各占一个角：分箱保真但长，VQ 短但粗，FAST 在中间，还能用 \(\gamma\) 调节。

    5再一个视角：token 给出的是一个分布

    把动作离散化除了能复用语言模型，还有一个更深的好处。回归网络用 MSE 训练，学到的是条件均值 \(\mathbb E[a\mid s]\)（16.2 节）。如果示范者有时从左边绕过障碍、有时从右边，均值就落在两者中间，正好撞上障碍。而对 token 做分类时，网络输出的是一个完整的分布 \(\hl{prob}{p_\theta(k\mid s)}\)，两个峰可以同时存在。这是“多峰”问题的第一种解法；22.1 节会更仔细地讲 BC 为什么会平均掉多个模式，22.2 节的扩散策略是另一种解法。

    下图的状态 \(s\) 表示障碍相对机器人的位置，动作 \(a\) 是横向的转向量。\(s\) 越大，示范者越倾向于从右边（\(a>0\)）绕；\(s\) 在 0 附近时左右各占一半。左右两个模式之间 \(|a|<0.3\) 的红色带子代表撞上障碍。两个网络（同样的 [1, 32, 32] tanh 隐藏层）在同一批数据上实时训练：一个回归 \(a\)，一个把 \(a\) 均匀分成 \(B\) 个箱子后做分类。

    • 按“训练”至少 1500 步：在 \(s=0\) 处，分类网络把至少 20% 的概率分给左边（\(a<0\)），也把至少 20% 分给右边；回归网络的输出却停在两者之间的红色带子里。
    • 训练至少 1500 步后，把解码规则改为“期望”：在 \(s=0\) 处，\(\sum_k p_k\hat a_k\) 也落进了红色带子（\(|a|<0.3\)），和回归一样撞上障碍。
    反 token 化也是设计的一部分

    有了分布还得决定怎么把它变回一个动作。取最大（argmax）总选同一个模式，结果确定，但在两个模式概率接近时，\(s\) 的微小变化会让它在两个模式之间来回跳。采样真正保留了多峰性，但相邻两步可能各抽到一边，所以通常和动作分块（一次采样一整段，22.2 节）配合。取期望 \(\hl{mean}{\sum_k p_k\hat a_k}\) 看起来“更精确”，却正好把多峰性又平均掉了：它最小化的就是平方误差，和回归是一回事。

    6再看数学

    提示：把鼠标悬停在公式中带底色的符号上，图中对应的元素会被高亮（最近一次合并、图像块网格、箱子边界、DCT 系数、码本、分类分布、期望解码）。

    tokenizer 与训练目标

    一个 tokenizer 是一对映射：编码器 \(\mathcal E\) 把数据 \(\mathbf x\)（一句话、一张图、一段动作）变成整数序列 \(k_{1:n}\)，\(k_i\in\{0,\dots,V-1\}\)；解码器 \(\mathcal D\) 把整数序列变回数据 \(\hat{\mathbf x}=\mathcal D(\mathcal E(\mathbf x))\)。文字的 BPE 是无损的（\(\hat{\mathbf x}=\mathbf x\)），动作 tokenizer 都是有损的。自回归模型按链式法则分解序列的概率（19.4 节），以观测 \(o\)（图像和指令的 token）为条件，用交叉熵训练：

    $$ p_\theta(k_{1:n}\mid o)=\prod_{i=1}^{n}p_\theta(k_i\mid k_{<i},o) $$ $$ \mathcal L(\theta)=-\sum_{i=1}^{n}\log p_\theta(k_i\mid k_{<i},o) $$

    每个 token 最多携带 \(\log_2V\) 比特（4.11 节）。动作 tokenizer 的“码率”是每秒 token 数乘以每个 token 的比特数；推理时每个 token 需要一次前向计算，所以每秒 token 数也直接决定了自回归解码的延迟。

    BPE 与图像块

    BPE 从基本符号表（字符或字节）出发，每一步找出语料中相邻出现次数最多的一对符号，把它合并成新符号，直到达到预定的字典大小（\(\#(a\,b)\) 是语料里 \(b\) 紧跟在 \(a\) 后面出现的次数）：

    $$ \hl{merge}{(a,b)}=\arg\max_{(a,b)}\ \#(a\,b),\qquad a\,b\ \to\ ab,\qquad V\leftarrow V+1 $$

    编码新文本时按学到的顺序依次应用这些合并。以字节作为基本符号（GPT-2 的“字节级 BPE”）时，任何字符串都能编码，FIG 1 里红色虚线框那种“没见过的字符”就不会出现。图像没有字典，\(H\times W\times3\) 的图片切成 \(n=HW/\hl{patch}{P}^2\) 块，每块拉直成 \(3P^2\) 维向量 \(\mathbf x_i\)，经过同一个线性层 \(\mathbf z_i=W_e\mathbf x_i+\mathbf p_i\)（\(\mathbf p_i\) 是位置编码）。注意力的代价约为 \(n^2\)，所以把 \(P\) 减半，token 数变成 4 倍，注意力的代价变成 16 倍。

    均匀分箱

    对动作的每一维 \(d\)，用训练数据定出范围 \([a_{\min},a_{\max}]\)（最小–最大，或 1% 与 99% 分位数），分成 \(N\) 个箱子：

    $$ \hl{delta}{\Delta}=\frac{a_{\max}-a_{\min}}{N},\qquad k=\min\!\Big(N-1,\ \max\!\Big(0,\Big\lfloor\frac{a-a_{\min}}{\Delta}\Big\rfloor\Big)\Big),\qquad \hat a=a_{\min}+\big(k+\tfrac12\big)\Delta $$

    范围内的值误差 \(|a-\hat a|\le\Delta/2\)。如果值在每个箱子里大致均匀地分布，误差就是 \([-\Delta/2,\Delta/2]\) 上的均匀分布，方差 \(\Delta^2/12\)，均方根 \(\Delta/\sqrt{12}\approx0.29\Delta\)：箱子数翻倍，误差减半，代价只是每个 token 多 1 比特。范围外的值被截断到端点的箱子里，误差可以任意大，所以分位数范围只适合截掉真正罕见的值。每秒的 token 数是 \(D\cdot f\)，与 \(N\) 无关。

    FAST：正交变换 + 取整 + 无损压缩

    对一维动作 \(a_0,\dots,a_{H-1}\)，正交归一的 DCT-II 及其逆变换是

    $$ \hl{coef}{c_k}=s_k\sum_{n=0}^{H-1}a_n\cos\frac{\pi(n+\frac12)k}{H},\qquad a_n=\sum_{k=0}^{H-1}s_k\,c_k\cos\frac{\pi(n+\frac12)k}{H},\qquad s_0=\sqrt{\tfrac1H},\ s_{k>0}=\sqrt{\tfrac2H} $$ $$ q_k=\operatorname{round}(\gamma\,c_k),\qquad \hat c_k=q_k/\gamma $$ $$ \sum_n(a_n-\hat a_n)^2=\sum_k(c_k-\hat c_k)^2\le\frac{H}{4\gamma^2}\ \Longrightarrow\ \sqrt{\tfrac1H\textstyle\sum_n(a_n-\hat a_n)^2}\le\frac{1}{2\gamma} $$

    写成矩阵，DCT 就是一个 \(H\times H\) 的正交矩阵（1.10 节），它保持长度，所以系数上的误差平方和等于时间域里的误差平方和（Parseval 等式）。每个系数取整的误差不超过 \(1/(2\gamma)\)，于是每个样本的均方根误差不超过 \(1/(2\gamma)\)，与 \(H\) 无关：\(\gamma=10\) 时上界是 0.05，FIG 4 里各种设置下实测在 0.014 到 0.029 之间（被取成 0 的小系数误差小于上界）。平滑信号的 \(c_k\) 随 \(k\) 增大迅速变小，满足 \(|\gamma c_k|<\tfrac12\) 的系数都变成 0，非零整数的个数大致只取决于轨迹里有多少“弯”，这才是 BPE 能压缩的东西。FAST 把系数矩阵按列展平（先放所有维的第 0 个系数，再放所有维的第 1 个……），论文的解释是先预测低频成分，生成的轨迹更稳定。

    向量量化

    码本 \(\{\hl{code}{\mathbf e_k}\}_{k=1}^{K}\subset\R^{2L}\) 由 k-means 学出，它最小化训练片段 \(\mathbf v_j\) 到最近码字的平方距离；编码就是最近邻查表。残差 VQ 再用第二本码本量化剩余误差：

    $$ \min_{\mathbf e_{1:K}}\sum_j\min_k\|\mathbf v_j-\mathbf e_k\|^2 $$ $$ k^{(1)}=\arg\min_k\|\mathbf v-\mathbf e^{(1)}_k\|,\qquad k^{(2)}=\arg\min_k\|\mathbf v-\mathbf e^{(1)}_{k^{(1)}}-\mathbf e^{(2)}_k\| $$

    每级每个片段 1 个 token、\(\log_2K\) 比特，每秒 \(S f/L\) 个 token（\(S\) 是级数）。FIG 5 里 \(K=16\)、\(L=4\)、单级的码率只有每秒 \(5\times4=20\) 比特；同样 20 Hz 下 256 个箱子的分箱是 \(40\times8=320\) 比特。码率低当然有代价：这本码本只能表示 16 种“动作片段”。

    分类头与解码

    $$ \hl{prob}{p_\theta(k\mid s)}=\operatorname{softmax}\big(\mathbf z_\theta(s)\big)_k,\qquad \mathcal L=-\log p_\theta\big(k(a)\mid s\big) $$ $$ \bar a=\hl{mean}{\textstyle\sum_k p_k\,\hat a_k}=\arg\min_{\hat a}\ \mathbb E_{k\sim p}\big[(\hat a_k-\hat a)^2\big] $$

    交叉熵的最优解是 \(p_\theta(k\mid s)\) 等于数据里 \(a\) 落进第 \(k\) 个箱子的条件概率，多少个峰都能表示。而期望解码最小化的是平方误差，它和 MSE 回归的最优解 \(\mathbb E[a\mid s]\) 只差箱子的量化误差，所以又回到了“平均掉模式”的老问题。也要注意：交叉熵不知道箱子是有顺序的。把真值在第 128 个箱子的动作预测成第 129 个，和预测成第 0 个，受到的惩罚完全一样，网络必须从数据里自己学到“相邻箱子相似”。

    7机器人中的它：VLA 怎样“说出”动作

    下表是几种有代表性的做法。它们几乎都从“每维 256 个均匀箱子”开始，后来的工作主要在改范围（分位数）、改序列长度（FAST、VQ）或干脆不用离散 token（ACT、扩散策略）。

    工作动作怎样变成 token
    Trajectory Transformer (Janner et al., 2021)把状态、动作和回报的每一维分别离散化，整条轨迹当作一个序列建模。
    Gato (Reed et al., 2022)连续值先做 μ-law 压扩到 \([-1,1]\)，再均匀分成 1024 个箱子，箱子的编号排在文字 token 之后，和文字共用同一个 Transformer。
    RT-1 (Brohan et al., 2022)机械臂、移动底座和模式切换的每个动作维度各分成 256 个均匀箱子；模型一次输出当前时刻的全部动作 token。
    RT-2 (Brohan et al., 2023)同样的 256 个箱子，但直接写成语言模型的文字 token：PaLI-X 版本用表示整数的 token，PaLM-E 版本挪用 256 个最少使用的 token，让 VLM 原样“说出”动作。
    OpenVLA (Kim et al., 2024)7 维动作，每维 256 个箱子，范围取训练数据的 1% 和 99% 分位数（FIG 3 的做法），覆盖 Llama 分词器里 256 个最少使用的 token。
    BeT (Shafiullah et al., 2022)用 k-means 把动作聚成若干类，Transformer 预测类别（离散，处理多峰）再加一个连续的偏移量（补回精度）。
    VQ-BeT (Lee et al., 2024)用残差 VQ 把动作块编码成几级码字，再预测码字和偏移量。
    FAST / π0-FAST (Pertsch et al., 2025)DCT + 取整 + BPE；另外发布了在约 100 万条 1 秒动作块上训练的通用版 FAST+。论文报告，与扩散式 VLA 性能相当，训练时间最多缩短 5 倍。
    ACT (Zhao et al., 2023)不做离散化：一次回归出一整块连续动作（动作分块），并用时间集成平滑块与块之间的衔接，见 22.2 节。

    FAST 论文的表 I 给出了 1 秒动作块的 token 数，可以和 FIG 3 的 \(D\cdot f\) 公式对照：BridgeV2（7 维、5 Hz）逐步分箱 35 个、FAST 20 个；DROID（7 维、15 Hz）105 对 29；叠 T 恤（双臂 14 维、50 Hz）700 对 53。分箱的 token 数严格等于 \(D\cdot f\)，而 FAST 在不同频率下大致都在每条手臂 20 到 30 个之间，和 FIG 4 看到的一样：它跟着轨迹的复杂度走，不跟着频率走。

    真实系统里

    序列预算：一个 VLA 的输入通常是几路相机，每路几百个图像 token（224×224、14×14 的块是 256 个），加上几十个指令 token；动作 token 排在最后逐个生成。逐步分箱时，一步 7 个 token 意味着 7 次顺序的前向计算，这限制了控制频率，也是 FAST 和动作分块想要解决的问题之一。 归一化统计量是模型的一部分：分箱和 FAST 的范围、分位数、\(\gamma\) 都是从训练数据算出来的，部署时必须用同一套统计量反 token 化；换一台机器人、换一个数据集，往往要重新计算。 夹爪：夹爪开合常是接近二值的阶跃，对分箱无所谓，但对 DCT 来说阶跃需要很多高频系数，还原时会在跳变两侧出现振荡（吉布斯现象）。 不离散化的路线：π0 用流匹配（19.7 节）直接生成连续的动作块，Diffusion Policy 用扩散（22.2 节），它们不需要动作 tokenizer，但也就不能直接复用语言模型的输出头。

    8常见误区

    误区 1：用最小–最大值定范围

    真实数据里总有传感器故障、遥操作时的猛拉、单位写错的示范。FIG 3 里一个故障样本就让 \(x\) 维的箱子宽了三倍，正常动作的误差几乎变成三倍。用分位数定范围（OpenVLA 用 1% 和 99%），或者先清洗数据。反过来，分位数会截断真正极端的动作；如果任务需要偶尔的大动作（快速撤回），要检查它们没有被截掉。

    误区 2：以为箱子越多越好、频率越高越好

    箱子多了，每个箱子分到的训练样本就少，softmax 更宽，而交叉熵又不知道相邻箱子相似，所以需要更多数据才能学好。频率高了，逐步分箱的序列按 \(D\cdot f\) 变长，而且大部分 token 只是重复前一个（FIG 3），模型容易学成“抄上一个”。256 个箱子是常见的默认值，不是定律；高频任务应该先考虑 FAST 这类压缩，或者动作分块。

    误区 3：用期望值解码多峰分布

    FIG 6：期望解码最小化平方误差，和回归一样把左右两个模式平均成正中间。想保留多峰性就要采样或取最大，并且要保证一段动作内部的选择一致（一次采样一整块），否则机器人会在两个模式之间来回切换，哪个都完成不了。

    误区 4：不处理“非法”的 token 序列

    语言模型可以在动作的位置上输出一个文字 token，或者在 FAST 里生成一串解码后系数个数不等于 \(D\times H\) 的 token。部署时要约束解码（只允许动作 token 出现在动作位置），并对 FAST 解码出的系数做补零或截断。分箱 tokenizer 也一样：输出的编号必须落在 \(0,\dots,N-1\) 里。

    误区 5：忽略块与块之间的衔接

    一个 token 代表的动作越长（VQ 的片段、FAST 的 1 秒块、动作分块），块内越平滑，块与块之间的接缝就越显眼：FIG 5 里 \(K=16\)、\(L=10\) 时片段边界的平均跳变约 0.8，是 \(L=4\) 时的三倍多。常见的补救：让块之间重叠并做时间集成（ACT），只执行每块的前一部分再重新规划（滚动时域，Diffusion Policy），或者在下一块的条件里加入上一块的结尾。

    9小练习

    1. 一条 7 维动作的机械臂以 50 Hz 控制，每维 256 个均匀箱子，逐时刻分箱。1 秒的动作需要多少个 token？
    每个时刻每一维一个 token：\(D\cdot f=7\times50=350\)。箱子数 256 只决定每个 token 能取多少个值（8 比特），不影响 token 个数（选项 D 把两者混淆了）。FAST 论文里 14 维、50 Hz 的叠 T 恤任务正好是 700 个。
    2. 为什么 OpenVLA 用训练数据的 1% 和 99% 分位数，而不是最小值和最大值，来确定每一维的箱子范围？
    箱子宽度 \(\Delta=(a_{\max}-a_{\min})/N\)。FIG 3 里一个记成 4.0 的故障值让 \(x\) 维范围从约 1.55 变成约 4.75，16 个箱子时 RMSE 从 0.023 涨到 0.065。分位数不改变 token 数（选项 A），也不会让误差为零（选项 C），代价是截断最极端的 1%。
    3. 在 FAST 里把缩放因子 \(\gamma\) 加倍，会怎样？
    \(q_k=\operatorname{round}(\gamma c_k)\)：\(\gamma\) 越大，取整越细，误差越小，但满足 \(|\gamma c_k|<\tfrac12\) 而变成 0 的系数越少，整数也越大，BPE 能压缩的就越少。系数个数永远是 \(D\times H\)（选项 C 错）。BPE 无损，但损失发生在取整这一步（选项 D 错）。FIG 4 里 50 Hz 时 \(\gamma\) 从 10 到 30，平滑轨迹的 token 从 13 增到 17，RMSE 从 0.015 降到 0.0055。
    4. 一个对动作箱子做分类的策略在左右两种示范上训练得很好。部署时用期望值 \(\sum_kp_k\hat a_k\) 解码，在两种示范各占一半的状态下会发生什么？
    期望最小化平方误差，等于把分布平均成一个点。分布本身是多峰的（网络学对了），是解码把它毁掉了。选项 A 描述的是采样，选项 B 描述的是取最大。FIG 6 里切到“期望”就能看到 \(s=0\) 处的解码动作落进红色带子。
    5. 20 Hz 的 2 维动作，用 \(K=256\) 的单级 VQ 码本、片段长度 \(L=10\)。每秒多少个 token、多少比特？
    每 \(L=10\) 步（0.5 秒）一个 token，每秒 \(f/L=2\) 个，每个 \(\log_2256=8\) 比特，共 16 比特。选项 A 是同样频率下每维 256 个箱子的逐步分箱：码率高了 20 倍。码率这么低，片段内的细节只能靠码本里那 256 种形状来近似，所以 FIG 5 里 \(L=10\) 时边界跳变明显变大。
